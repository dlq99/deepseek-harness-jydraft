## 3. 已经定下来的（不要重新讨论）

### 3.1 分界线：判断进 DSH，执行留进程外

**判据是任务书自己的 R5**——「替代执行 → 直接自动；替代判断 → 保留人工干预点」：

```
创意 · (a) 视频理解 · (b) 片段筛选 · (c) 切片方案  → 判断 → DSH（preset + 插件 + 界面）
(d) 求解 · (e) 生成草稿 · 保真层/原子操作/编译     → 执行 → 进程外，DSH 通过 MCP 调它
```

**核心不进 DSH 的理由**：R6 要求核心不与剪映耦合；同一句话对宿主成立。核心一旦 `import '@deepseek-ai/cordis'`，就同时绑死剪映和 DSH 两个会变的东西（DSH 是 `0.1.7-rc.2`，`AGENTS.md` 原文：*Public APIs are pre-stable; update every consumer*）。

### 3.2 三组对应关系

| 产品概念 | DSH 机制 | 源码位置（已核） |
|---|---|---|
| 项目 | workspace（带会话有序账本） | `ctx.workspaceRegistry` |
| 阶段 | session + agent | `ctx.agents.create({ sessionId, agentPreset, parentAgent, delegationDepth })` |
| 阶段的定制 | **agent preset** = 一份子插件行列表 | `CreateAgentOptions.agentPreset`（`packages/core/agent/src/index.ts:85`） |

### 3.3 阶段定制用三个专用包

| 包 | 作用 |
|---|---|
| `@deepseek-ai/dsh-agent-preset` | 在 Cordis YAML 里定义 Agent 的子插件列表 |
| `@deepseek-ai/dsh-agent-preset-registry` | 声明式选择工具/提示词/技能；配置失败显示在列表里；**现有 Agent 保留已用组合** |
| `@deepseek-ai/dsh-persona` | **换掉 agent 身份。** `complete: true` → 前缀成为唯一系统提示词 |

**`dsh-persona` 的一句话是整件事的关键**：*没有这一行，preset 能改变 agent 的工具，却永远改不了它的身份。*

**preset 里能装的**（都是插件行）：`guard/` 护栏 · `compaction/` 压缩 · `context/` 上下文来源 · `skill/` 技能 · `persona` 身份。

### 3.4 界面：五个顶级槽位

`packages/client/ui-layout/src/client/AppFrame.tsx:30` 的 `PropsRenderSlots<'sidebar' | 'main' | 'rightbar' | 'shell.overlay' | 'shell.leading'>`

**主区替换的机制**（同文件 L42）：`renderSlot('main', {}, { entryKey: panelId ?? 'conversation' })`
→ 注册自己的 keyed cell，用 `ctx.layout.selectPanel(id)` 选中。**`conversation` 只是兜底 key，不能被移除**（并存 + 切换，不是拿掉）。

### 3.5 消息管线：不要建

DSH 官方文档**自己声明**不提供投递保证：`webhook.zh.md`「没有队列、重试、去重、执行状态、崩溃重放」；`schedule.zh.md`「错过的发生时点不会累积」；`jobs/README.md` 自称 process-local storage；`packages/` 下**没有任何 queue/bus/broker 包**。

**五个阶段是固定顺序，同进程直调即可。** 要异步就落 SQLite 的 pending 表自己管四态。

## 5. 三条纪律（违反会破坏隔离）

1. **`jydraft/` 之外不改任何东西。** 需要改 `packages/` 时先问扩展点能不能做到。提交前跑 `node jydraft/scripts/check-isolation.mjs`。
2. **不改仓库根的配置**（`.rgignore` / `tsconfig` / `package.json`）。要配置搜索就用 `--ignore-file`。
3. **生成物不要手改**（`docs/00-*`、`data/*`）。改规则改脚本再重新生成。

**为什么「不改源码」不只是洁癖**：一旦改了 `packages/`，从上游按需 cherry-pick 一个修复就可能冲突——于是你就不会拉了，于是永久失去上游。**隔离让「按需拉取」这个选项保持便宜。**

## 8. 关键事实速查（都已核过源码）

| 问题 | 答案 |
|---|---|
| 一个工作区能挂几个会话 | 多个。workspace 的定义就是「带归属于它的会话的**有序账本**」 |
| 会话能程序化创建吗 | 能。`ctx.agents.create(options)` / `resume(options)` |
| preset 什么时候选定 | **创建 agent 时**。`CreateAgentOptions.agentPreset?: string` |
| 阶段串联有血缘吗 | 有。`parentAgent` + `delegationDepth`（注释称 recursion budget） |
| 能用事件回放做种子吗 | 能。`CreateAgentOptions.seed?: readonly SessionEvent[]` |
| 能换掉整个系统提示词吗 | 能。`dsh-persona` 的 `complete: true` |
| 能关掉动态上下文吗 | 能。`dsh-persona` 的 `includeRuntimeContext: false` |
| 动态数据注入怎么做 | `ctx.systemPrompt.context()`（`PromptContext`，**缓存安全的 durable user-role snapshot**） |
| 一次性注入 | `agent.inject()`（**带来源标识**） |
| 请求推导前改写输入 | `agent/pre-step`（**唯一的 waterfall**） |
| 改模型所见但不改日志 | 插件拥有的**消息投影**（要求纯） |
| agent loop 上有多少扩展点 | **18 个**（agent 9 / 工具流水线 6 / LLM 线 3） |
| loop 能改吗 | 规则是「*Plugins, not loop changes*」：新行为放扩展点；改 loop 要更新架构文档 |
| 界面怎么贡献 | `ctx.slots.register()` / `ctx.slots.inject(key, cb)`；`priority` 是**遮蔽优先级** |
| 主区怎么换 | `main` keyed slot + `ctx.layout.selectPanel(id)` |
| DSH 会把数据传出去吗 | **会。** 基础组合包**默认开启会话日志上传** + OTel；导出可能含消息文本、工具参数、结果、**工作区路径**。关闭：`session-log-deepseek.enabled: false` + `DSH_TELEMETRY_MODE=DISABLED` |
| 一条不能碰的不变量 | **Model-visible ⟺ logged**：到达模型请求的内容必须能从会话日志重建。**所以「注入了但不记录」在设计上不支持** |
